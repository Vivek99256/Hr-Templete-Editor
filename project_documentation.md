# HR Template Editor - Full Project Guide

This document is a comprehensive guide to the **HR Template Editor**. It covers everything from setting up the project locally to understanding the core architecture, the drag-and-drop mechanics, and how to extend or integrate the application with a backend in the future.

---

## 1. Project Overview

The HR Template Editor is a web-based application designed to allow HR professionals and administrators to dynamically create, edit, and manage document templates (like offer letters, certificates, policy documents, etc.). Instead of relying on static word documents, users can drag and drop text blocks, images, tables, and shapes onto a canvas, edit them visually, and save the templates for later use.

### Goals
- Provide a responsive, WYSIWYG (What You See Is What You Get) editing experience.
- Ensure the output is structured data (JSON) rather than arbitrary HTML, allowing for easy reconstruction, versioning, and potential PDF generation later.
- Maintain a clean codebase where UI concerns are strictly separated from data storage logic.

## 3. Technology Stack & Libraries

### Core App Framework
-   **[Next.js 16 (App Router)](https://nextjs.org/)**: React framework handling routing, Server Components (though this app heavily uses Client Components due to the interactive nature of the editor), and structure.
-   **[TypeScript](https://www.typescriptlang.org/)**: Ensures type safety across the entire application, which is crucial when dealing with complex nested JSON trees generated by the editor.
-   **[Tailwind CSS](https://tailwindcss.com/)**: Primary styling engine used for almost all UI components, providing utility classes for rapid layout building.

### The Drag-and-Drop Engine
-   **[`@craftjs/core`](https://craft.js.org/) & [`@craftjs/layers`](https://www.npmjs.com/package/@craftjs/layers)**: This is the heart of the application. Craft.js provides a React-based drag-and-drop page builder system. Unlike libraries like `react-beautiful-dnd` which just move DOM nodes, Craft.js manages an internal state tree of React components, allowing us to serialize the page structure to JSON and deserialize it back into React components later.

### Rich Text Editing
-   **[`@tiptap/react`](https://tiptap.dev/)**: A headless rich-text editor based on ProseMirror. It is embedded inside our `TextBlock.tsx` to allow users to edit text directly on the canvas, apply bold/italics, change colors, and manage alignment.
-   **Extensions**: `@tiptap/starter-kit`, `@tiptap/extension-color`, `@tiptap/extension-text-style`, etc., are loaded to configure TipTap's capabilities.

### UI Components & Interactivity
-   **[Radix UI](https://www.radix-ui.com/)**: Unstyled, accessible React components (`@radix-ui/react-popover`, `@radix-ui/react-tabs`). We use these as the foundation for our custom UI elements like context menus and the settings panel tabs, styling them with Tailwind.
-   **[`re-resizable`](https://github.com/bokuweb/re-resizable)**: A React component used to wrap elements like Images or Shapes, allowing the user to click and drag edges to change their dimensions on the canvas.
-   **`react-color`**: Provides the color picker interface found in the Settings Panel.
-   **`lucide-react`**: The icon library used throughout the application.

## 4. Architectural Deep Dive

The project strictly follows **Clean Architecture** patterns to ensure long-term maintainability.

### The Three Layers

#### 1. Core / Domain Layer (`core/`)
This is the innermost layer. It knows nothing about React, Next.js, or LocalStorage.
-   **`models/Template.ts`**: Defines what a Template *is*. It's a simple TypeScript interface: `{ id: string, name: string, content: string, createdAt: string, updatedAt: string }`. The `content` string is the serialized JSON from Craft.js.
-   **`services/TemplateService.ts`**: Contains the business logic operations (`saveTemplate`, `getTemplate`, `getAllTemplates`, `deleteTemplate`). It takes an injected interface (`TemplateAdapter`) to perform these operations, remaining ignorant of *how* the data is actually stored.

#### 2. Infrastructure / Data Layer (`infrastructure/`)
This layer implements the interfaces defined by the Core layer.
-   **`adapters/TemplateAdapter.ts`**: An interface defining methods like `save()`, `getById()`, etc.
-   **`adapters/LocalStorageAdapter.ts`**: A concrete implementation of `TemplateAdapter`. It implements the logic to save and retrieve the `Template` objects specifically to and from the browser's `localStorage` API.

#### 3. Presentation / UI Layer (`components/` & `app/`)
This layer contains all the React/Next.js code. It communicates with the Core layer via the Services.
-   **`app/`**: Next.js App Router.
    -   `/dashboard/templates/page.tsx`: Shows the list of available templates. Uses `TemplateService` to fetch data.
    -   `/editor/[templateId]/page.tsx`: The main editing interface.
-   **`components/editor/`**: The shell of the editor application.
    -   `Topbar.tsx`: Contains the "Save" and "Back" buttons.
    -   `Toolbox.tsx`: The sidebar containing draggable elements. Every item here defines a `ref={(ref) => connectors.create(ref, <ComponentName />)}` which tells Craft.js what component to instantiate when dropped.
    -   `EditorCanvas.tsx`: The main area where blocks are dropped.
    -   `SettingsPanel.tsx`: Dynamically reads the properties of the currently *selected* block in Craft.js and renders inputs (sliders, color pickers, text inputs) to modify those properties.
-   **`components/blocks/`**: The actual "User Components" defined for Craft.js. Every block defined here must have a `craft` static property defining its metadata, rules, and settings component.
    -   `TextBlock.tsx`: Integrates TipTap.
    -   `ImageBlock.tsx`: Integrates `re-resizable`.
    -   `ContainerBlock.tsx`: Acts as a drop zone for *other* blocks.

## 5. Understanding the Data Flow (Saving a Template)

When a user finishes editing and hits "Save", this is exactly what happens behind the scenes:

1.  **User Action**: User clicks the "Save" button in `components/editor/Topbar.tsx`.
2.  **State Serialization**: The Topbar component calls `query.serialize()` provided by Craft.js. Craft.js takes the current React tree inside the editor context and converts it into a structured JSON string.
3.  **Service Invocation**: The Topbar component calls the `TemplateService.saveTemplate(template)` method, passing in a `Template` object that contains the newly serialized JSON string.
4.  **Adapter Execution**: `TemplateService` delegates the save action to its injected adapter, currently the `LocalStorageAdapter`.
5.  **Persistence**: `LocalStorageAdapter` reads the existing array from `localStorage`, updates or appends the new template data, runs `JSON.stringify()`, and writes it back to `localStorage` under the `hr_templates` key.
6.  **Confirmation**: A toast or alert notifies the user that the save was successful.

## 6. How to Add a New Block Type

To extend the editor with a new draggable element (e.g., a "Signature" block), you must follow these steps:

1.  **Create the Block Component**: Create a new file in `components/blocks/SignatureBlock.tsx`.
2.  **Define Props**: Define the properties the block will need (e.g., `interface SignatureProps { color: string, width: number }`).
3.  **Build the Component**: Write the React component that renders the signature UI based on those props.
4.  **Define Craft Settings**: Create a complementary settings component (`SignatureSettings`) that contains the UI to modify the `SignatureProps`.
5.  **Attach Craft Metadata**: Add the `craft` static property to your main component:
    ```typescript
    SignatureBlock.craft = {
        displayName: 'Signature',
        props: { color: '#000', width: 200 }, // Default props
        related: { settings: SignatureSettings } // Attach the settings UI
    }
    ```
6.  **Register the Block**: Open `app/editor/[templateId]/page.tsx` and add your `SignatureBlock` to the `<Editor resolver={{ ... }}>` array so Craft.js knows how to deserialize it.
7.  **Add to Toolbox**: Open `components/editor/Toolbox.tsx` and add a new draggable button that instantiates `<SignatureBlock />`.

## 7. Future Backend Integration Roadmap

Currently, the application uses Local Storage. The Clean Architecture makes transitioning to a real backend (like a standard REST API built with Laravel, Node.js, or direct Database integration) incredibly straightforward and safe.

### Steps to Integrate an API Backend:
1.  **Create a New Adapter**: In `infrastructure/adapters/`, create `ApiTemplateAdapter.ts`. This class will implement the same `TemplateAdapter` interface as the LocalStorage version.
2.  **Implement Fetch Logic**: Inside `ApiTemplateAdapter.ts`, implement the interface methods using `fetch` or `axios` to make HTTP calls to your real backend endpoints (e.g., `POST /api/templates`, `GET /api/templates/:id`).
3.  **Swap the Adapter**: Where you instantiate the `TemplateService` (likely in your Next.js pages or custom hooks), change the injection:
    ```typescript
    // OLD
    // const adapter = new LocalStorageAdapter();
    // const templateService = new TemplateService(adapter);

    // NEW
    const adapter = new ApiTemplateAdapter('https://your-api.com/api');
    const templateService = new TemplateService(adapter);
    ```
4.  **Result**: You have now connected the application to a real database without modifying a single line of React code, UI logic, or the core domain models. The frontend editor remains completely oblivious to where the JSON data is actually going, as long as the adapter fulfills the contract.
